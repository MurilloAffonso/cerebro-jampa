## Decisões de Posicionamento

### 1. WhatsApp é CTA Principal (Obrigatório)
**Decisão:** Não email, não formulário. WhatsApp clicável em TODOS os places: site, GMB, TripAdvisor, Instagram
**Por quê:** Turista em JP tem WhatsApp, resposta é rápida, conversão é imediata
**Implementação:** Botão verde, grande, em destaque. Mencionado na home, clusters, passeios, FAQ

### 2. Preço Deve Ser Visível (Estratégico)
**Decisão:** Não "consulte WhatsApp". Preço claro no site (ex: "R$ 60 compartilhado")
**Por quê:** Reduz fricção, turista não perde tempo com conversa sobre preço, foca em "qual passeio" não "quanto custa"
**Implementação:** Cada página de passeio tem preço destacado. FAQ tem "Quanto custa?" com resposta.

### 3. Murillo é Rosto da Marca (Crítico)
**Decisão:** Não agência impessoal. Murillo em foto, voz, assinatura, stories
**Por quê:** Pessoa = confiança. Diferencial sustentável vs. agência genérica.
**Implementação:** Foto de Murillo em homepage, "Sobre Nós", blog, Instagram. Mensagens assinadas "Murillo"

### 4. Cadastur e Avaliação no Topo (Prova Social)
**Decisão:** "Cadastur 52.077.577 — Ativo" + "4.9/5 ⭐" aparecem na homepage, acima da dobra
**Por quê:** Turista valida legitimidade em 5 segundos. Elimina desconfiança.
**Implementação:** Seção "Por Que Confiar em Vem Passear" na homepage com Cadastur + rating

### 5. Tábua de Maré é Diferencial Operacional (Honestidade)
**Decisão:** Mencionar explicitamente "Passeio depende de maré baixa" em Seixas, Areia Vermelha, Picãozinho
**Por quê:** Transparência (não false promise). Turista valoriza honestidade.
**Implementação:** Cada página de passeio com maré tem aviso claro: "Sujeito à tábua de marés"

### 6. Home Precisa Ser Mobile-First (Obrigatório)
**Decisão:** Site é projetado para mobile PRIMEIRO, depois desktop (não vice-versa)
**Por quê:** 70-80% de turista acessa via mobile (já em JP)
**Implementação:** Teste em mobile antes de considerar pronto. CTA grande (thumb-friendly). Texto legível.

### 7. Não Competir por Preço Ultra-Baixo (Filosofia)
**Decisão:** "Preço justo" é posicionamento. Vem Passear não faz "mega promo" ou "menor preço".
**Por quê:** Race to bottom (só quem corta margem ganha). Vem Passear compete em confiança + atendimento.
**Implementação:** Copy não menciona preço baixo. Mensagem foca em "valor" não "barato".

### 8. Competir por Confiança, Atendimento e Orientação (Diferencial)
**Decisão:** Os 3 pilares de Vem Passear são: "Vou te ajudar" + "Respondo rápido" + "Confiança"
**Por quê:** Já tem 4.9/5, Cadastur ativo, Murillo como especialista. Isso é imbatível vs. concorrência.
**Implementação:** Cada página comunica: orientação (ajudar turista), rapidez (WhatsApp), confiança (Cadastur + avaliação)

### 9. Páginas de Passeio Devem Consultar Catálogo (Operacional)
**Decisão:** ANTES de gerar qualquer página de passeio, consultar `_conhecimento/passeios.md`
**Por quê:** Uma fonte de verdade. Sem duplicação. Consistência garantida.
**Implementação:** Workflow: Catálogo → Página (copywriter puxa dados, não inventa)

## Decisões de Conteúdo

### 12. Blog Educativo Obrigatório (Tráfego)
**Decisão:** Mínimo 20 posts sobre turismo, maré, época, operação, dicas
**Por quê:** Tráfego de longo prazo. Posiciona expertise. Ninguém mais faz isso.
**Temas:** Maré, melhor época, o que levar, guias por praia, comparativos, sazonalidade

### 13. Landing Pages de Persona (Conversão)
**Decisão:** 4 landing pages: Famílias, Casais, Morador Local, Mochileiro
**Por quê:** Conversão alta (turista já filtrou por tipo). Sem homepage genérica.
**Implementação:** Cada landing tem: "Nossos passeios ideais para [persona]" + 2-3 passeios recomendados

### 14. FAQ Integrada com Schema (Featured Snippets)
**Decisão:** 15 perguntas estratégicas respondidas + JSON-LD FAQPage Schema
**Por quê:** Featured snippets = cliques de graça. Google mostra resposta direto.
**Temas:** Preço, como reservar, segurança, maré, confiança, operacional

## Decisões de Canais

### 15. Multi-Canal Obrigatório (Distribuição)
**Decisão:** Não só site. Presente em: Site + GMB + TripAdvisor + Viator + Instagram
**Por quê:** Turista encontra em múltiplos pontos. Confiança concentrada.
**Prioridade:** Site + GMB (imediato) → TripAdvisor (semana 2) → Viator (semana 3) → Instagram (contínuo)

### 16. Instagram com Conteúdo Real (Social)
**Decisão:** 3-5 posts/semana: stories, reels, carousels. Não stock photo.
**Por quê:** Turista descobre em Instagram, clica DM, conversa com Murillo
**Padrão:** Passeio real + dica + prova social. Respondemos rápido (diferencial).

## Decisões de Operação Claude Code (NEW — 2026-04-25)

### 17. Modelo IA Padrão: Sonnet 4.6 (Oficial)
**Decisão:** Claude Sonnet 4.6 é o modelo padrão de 99% das tarefas
**Por quê:** Balanço ideal entre qualidade, velocidade e custo. Suficiente para 95%+ do trabalho
**Exceções:** Opus 4.7 para decisões estratégicas complexas (~1%). Haiku 4.5 para tarefas triviais (~5%)
**Implementação:** Não especificar modelo (padrão Sonnet). Se precisar Opus: solicitar explicitamente

### 18. Stack Oficial: Next.js (Vinculante)
**Decisão:** Todas implementações do site usam Next.js (React, TypeScript, App Router, Tailwind CSS)
**Por quê:** Performance, SEO nativo, deployment simples (Vercel), comunidade forte
**Não é:** Wix, WordPress, Webflow (builders genéricos)
**Implementação:** Skill `programador-de-site` opera 100% em Next.js. Dados em `data/passeios.ts`

### 19. Pesquisa Aberta: Vault Primeiro, Web Depois
**Decisão:** Consulte `_conhecimento/` + `_memoria/` ANTES de pesquisar web
**Por quê:** Vault é fonte de verdade. Pesquisa web só para dados externos (benchmark, maré, ranqueamento)
**Permitido para:** Benchmark concorrentes, SEO local, validação de plataformas (TripAdvisor, Viator)
**Proibido para:** Dados que estão no vault (preço, passeio, tom de voz, decisões)
**Implementação:** Leia política completa em `_memoria/politica-uso-claude-code.md`

### 20. Claude Code é Modo Principal (Vinculante)
**Decisão:** Claude Code CLI é ambiente padrão para todo trabalho do projeto
**Por quê:** Contexto persistente, acesso direto ao vault, integração git, continuidade
**Aplicação:** Site, skills, templates, estrutura técnica, todas tarefas de execução
**Implementação:** Sempre usar Claude Code para trabalho local. Web app + outros modos são secundários
